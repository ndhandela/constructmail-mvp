### Caveats on the table above

- **`manifest.json` is not linked from `index.html`.** There is no
  `<link rel="manifest" href="...">` tag in `frontend/public/index.html`, so
  `favicon.ico`, `logo192.png`, and `logo512.png` are only reachable through a
  manifest file the browser has no way to discover. They are effectively dead
  in the current build. `manifest.json` also still has the untouched
  Create React App placeholder values (`"short_name": "React App"`,
  `"name": "Create React App Sample"`, `theme_color`/`background_color`
  don't match the POMAR palette) — worth fixing if the manifest is wired back
  up.
- **`favicon.ico` is not actually ICO-formatted.** `file` reports it as
  "PNG image data, 32 x 32" despite the `.ico` extension. Most browsers
  tolerate this, but it's not a true multi-resolution `.ico`.
- **`frontend/src/config/products.js`'s `logo` field is never read.** The only
  consumer of the `PRODUCTS` array that renders a live "tools" grid is
  `frontend/src/pages/Dashboard.js:85-101`, which renders
  `PRODUCT_ICONS[product.id]` (an emoji) instead of `product.logo`. So
  `/logos/constructmail.png` and `/logos/pomar.png` are referenced in data but
  not painted on screen anywhere today.
- **The "Built with DFW General Contractors" trust strip**
  (`frontend/src/pages/LandingPage.js:37-42`, `.trust-logos` /
  `.trust-placeholder`) does **not** use the POMAR logo or any image — it's
  plain text placeholders ("GC Partner", "DFW Builder", etc.), not a logo
  usage.
